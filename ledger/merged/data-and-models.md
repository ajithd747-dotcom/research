# Requirements Ledger — market-data, feature-engineering, models

Merged 2026-08-08. Raw rows in slice: 793 (Category = market-data, feature-engineering, or models,
including rows tagged with one of these three alongside other categories). Merged rows: 251.
Collapsed: 542.

Method: all seven raw files were read in full and grep-filtered on the Category column for
this slice's three tags (793 of ~3,244 total ledger rows). PLANNED/DECLINED status and phase
tags are taken from a full re-read of `ARCHITECTURE.md`, `FEATURES.md`, `DECISIONS.md`, and
`docs/superpowers/specs/2026-08-08-final-project-goal-design.md` (a dedicated sub-agent pass),
cross-checked against `research-corpus.md`'s own per-row citations. CLAIMED status was verified
directly against `trading-system/src/{capture,store,cost,statuswall}/` and `trading-system/tests/`
by reading the actual module and grepping for a caller — never assigned from a filename match or
from another ledger row's own "State" column. PRIOR-ART rows come from `early-repos.md`,
`early-repos-metaai-civilization.md`, and the `nse-botonly`/`crypto-bot`-prior-repo sections of
`crypto-bot-and-nse-botonly.md` and `nse-crypto-bot-final.md` — none of this code exists in the
current `trading-system` repo, which today contains only `capture/`, `store/`, `cost/`, and
`statuswall/` (zero feature-engineering or model code of any kind).

## Coverage caveats (read before trusting a row count)

- `crypto-bot-and-nse-botonly.md`'s rows citing `research/ARCHITECTURE.md`, `research/FEATURES.md`,
  `research/DECISIONS.md`, or an `IDEAS-*.md` file were treated as pure mirrors of the same
  citations in `research-corpus.md` and collapsed into one row each, per the task's own note that
  crypto-bot is a publish mirror of this project. Its `nse-botonly` rows and its handful of
  Layer-0 `IMPLEMENTED` rows (current repo) were kept.
- `nse-crypto-bot-final.md` contributed ~225 raw rows describing a ~300-node prior "CORTEX"
  brain architecture (`core/`, `nodes/`, `pattern_brain/`). Individually-named mechanisms
  (differentiable MoE gate, deep cascade, dynamic I/O bus, structure search, active-subnetwork
  routing, reflex-arc conditional compute, DCS router, column/segment network, etc.) were kept
  as separate rows because they are genuinely different mechanisms, not restatements. The
  underlying ~40-module "OSS model-family zoo" and several large curated-catalog "doc-claim only"
  rows were compressed into single summary rows rather than enumerated per sub-model, since the
  source itself reports them as one catalog.
- Pure vendor/library survey documents with no adopted decision and no built code (e.g. a
  standalone census of API endpoints, a shortlist of options-pricing libraries never wired in)
  were folded into the nearest capability row as a citation rather than given their own row,
  unless they represented a genuinely distinct, actionable finding.
- A strict reading of PLANNED was applied: a row is PLANNED only if `ARCHITECTURE.md`,
  `FEATURES.md`, `DECISIONS.md`, or the goal doc names it. Items appearing **only** in an
  `IDEAS-*.md` idea bank (a catalogue of candidate techniques, not an adopted plan) are
  UNRESOLVED unless prior-art code exists or the item was explicitly declined — this is a
  materially stricter bar than the raw ledger rows use (several of which self-label
  IDEAS-bank-only items "PLANNED"), and it is the reason this merge disagrees with some raw
  State values.
- This is not a claim of完全 (complete) coverage of 793 rows at 1:1 granularity — it is a
  best-effort merge at a defensible capability grain, done in one pass. Anything that looks
  like it should be here and isn't should be treated as a possible miss, not a confirmed absence.

### The five most important UNRESOLVED rows

1. **FE-024 / MD-044 — Correct per-feature/signal/strategy attribution.** The goal doc itself names this as a prerequisite for every learning loop, the meta-model, and the learning curve — and states plainly that nothing in the current plan specifies how it works. This is the single highest-leverage gap in the whole slice: everything downstream of it (MD-034 meta-model, MD-045 competency-based promotion, MD-052 green-day allocator objective) is unbuildable without it.
2. **MD-121 — SHAP/influence-functions/counterfactual-explanations/rule-extraction/concept-activation interpretability.** Catalogued as a coherent idea-bank section, nothing found built anywhere across all seven raw sources, and it is the most direct technical answer to the attribution gap above (item 1) — yet it has no adopted home in FEATURES/ARCHITECTURE/DECISIONS/goal-doc either.
3. **DM-064 — The breadth test ("THE GATE").** The goal doc's own stated mechanism for detecting "one macro bet wearing 1,290 hats" cannot run today because it depends on DM-006 (tail-tier capture, tested but with no CLI entry point). This is a gate the project considers load-bearing that is currently structurally impossible to execute.
4. **MD-142/143 — Hazard/competing-risks analysis over the strategy population.** A full survival-analysis treatment of *why and how strategies die* is catalogued in the research corpus but never adopted into a phase, distinct from the goal doc's narrower per-symbol setup-hazard item (MD-055, which *is* planned). Given how central promotion/decline decisions are to this project's design, the absence of a population-level hazard model is a real gap, not just an unexplored idea.
5. **MD-110 — Test-time adaptation.** Flagged in the project's own idea bank as "high value and high danger" — exactly the kind of capability that needs a decision (build it carefully, or explicitly decline it) rather than sitting unaddressed, since an accidental or informal version of it is easy to introduce by accident in any online-learning code path (MD-067's River learner already adapts online; nothing currently distinguishes disciplined test-time adaptation from that).

### The five most important PRIOR-ART rows

1. **MD-093 — The ~300-node OSS model-family zoo (`nse-crypto-bot-final`).** By far the largest single asset in this slice: gradient boosting, TS foundation models, transformers, GNNs, symbolic regression, causal discovery, chaos/dynamics, cross-sectional factors, denoising, reservoir computing, online learning, and probabilistic models, all behind one `NodeProtocol` contract with a working registry (`core/algo_registry.py`). If this project ever needs any of dozens of individually-catalogued "idea bank" techniques, the fastest path is very likely porting from here rather than building fresh — many of the UNRESOLVED and idea-bank-only rows above (MD-094 through MD-109) already have a home in this catalog.
2. **FE-046 / MD-076 — Full options-pricing stack (Black-76/BS Greeks, IV solver, IV rank/percentile, GEX, Max Pain, PCR, multi-leg payoff diagrams).** The current project's options segment (MD-059/063, FE-020/021/022/023) is entirely unbuilt and P3/P6, but nearly every individually-named sub-component already exists as tested, in some cases real-data-verified, code in `trading/options/*.py`. This is close to a direct port when the project reaches that phase.
3. **DM-006's tail_specs() near-miss, cross-referenced against DM-048's NSE clock-gated replay router.** Not a single row but a pattern worth calling out: the current repo already has a second, independently-built working implementation of "one clock-gated data path shared by backtest and live" in the NSE prior repo (`market_clock_gated_data_source_router.py`). That's strong external validation the current `ClockGatedReader` design (DM-010, CLAIMED) is sound, and a reference if replay-mode is ever needed for the current crypto project.
4. **MD-089 — Reflex-arc conditional-compute cascade with abstention as a first-class outcome.** A working, tested pattern for exactly the "signal expiry / abandon rather than force a call" requirement the current project has adopted for its directional bots (MD-016) but not yet built — this is close to a ready-made reference implementation for that specific requirement.
5. **FE-053 — Self-supervised Concept Discovery Engine (autoencoder → sparse-autoencoder probe → UMAP/HDBSCAN concept manifold).** A single working prior module that simultaneously satisfies two otherwise-UNRESOLVED idea-bank items (autoencoder market-state compression, mechanistic interpretability via sparse autoencoders) — a genuinely rare case in this corpus where one piece of prior code closes two separate open questions at once.

### Honesty about coverage

This merge processed all 793 raw rows in the slice and made an explicit status call on each, but the

made in a single pass at effort appropriate to the task, not an audited, multiply-reviewed
reconciliation. The market-data and the adopted-plan portions of feature-engineering/models (CLAIMED
and PLANNED-with-a-FEATURES/ARCHITECTURE/DECISIONS citation) are the most reliable parts of this
table, since those were checked directly against running code or precise document citations. The
PRIOR-ART and UNRESOLVED classification of the ~150 idea-bank-only "models" items is the least
reliable part — it depended on grep-based cross-referencing against a ~225-row prior-repo ledger
file read once, and a different reader doing the same cross-reference by hand might reclassify a
handful of the UNRESOLVED rows as PRIOR-ART or vice versa. Treat this ledger as a strong first draft
for prioritization discussions, not a final audited inventory.
