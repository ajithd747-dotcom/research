# Mined: nse-crypto-bot-final
Mined 2026-08-08. Files walked: approximately 876 of 1268 in-scope files (864 Python + 404 markdown, excluding vendor/ and tests/ which were out of scope for this pass) — roughly 69% by file count, weighted toward the highest-value material (all "brain"/broker_sense/strategy/trading-subsystem Python read at header+full-signature or full-body depth; root docs read in full; research/ read deeply for priority subdirectories and sampled elsewhere).

Coverage note: This inventory was produced by six parallel mining passes, one per repo region (trading/brain+broker_sense; trading/strategy+crypto; remaining trading/ subdirectories; core+cognition+memory+nodes+native+data+eval+tools+dashboard; root docs+run_*.py entry points; research/), each independently triaging (find + wc -l + grep for class/def/TODO/stub markers) before reading. The research/ pass itself further split across 4 of its own parallel sub-agents to cover its ~40 subdirectories. What was NOT read, and why:
- `vendor/` (24 Python files: vendored freqtrade, frequi, gplearn, vaderSentiment, generative_agents_memory, dfa, upstox_proto) — third-party dependency code, not this repo's own capability, excluded by design.
- `tests/` (239 Python files) — not walked directly in this pass; test names were used incidentally by some sub-passes as corroborating evidence but the directory was not inventoried file-by-file. A dedicated pass over `tests/` would likely surface additional evidence for IMPLEMENTED rows already captured and could catch a handful of features only visible through their test.
- `INDEX.md` (394KB, auto-generated master index) — only its first ~200 lines and section-header (`grep '^## '`) structure were read, not mined line-by-line; used only to cross-check directory-level file counts.
- Within `research/` (378 markdown + 18 Python files across ~40 subdirectories): all 18 Python files were read in full. Markdown was read in full for the highest-priority subdirectories (ai-scientist — all 14 files including 10 state snapshots; gate-rebuild — both synthesis docs, both wf_* journals, sampled agent-*.md transcripts; brain-os; brain-ultra-upgrade — all 5 docs; fable5 and its lessons/; direction-accuracy-program, direction-brain-mission, direction-equation-quest; strategies — all 10; market-making; remote-control; audits — all 11 named plus samples of the recurring independent-audit-* series; perf; plans; founder-intent). Sampled (not exhaustive) for the high-volume, lower-priority subdirectories: `research/video/*` (27 folders — full read for the ~10 technically-rich ones, first 10-25 lines for the remaining ~16 login-walkthrough/promo clips; hundreds of frame images never opened, their content is already described in the notes/understanding files), `research/visual-qa/*` (22 folders — 5 read directly, the recurring automated-QA pattern confirmed to repeat across the rest via directory listing rather than read individually), `research/uploads-20260717` and `research/practice-notebook` (each read in full, single-file scope). In total roughly 280 of 396 research/ files were opened.
- Within `trading/strategy/` (75 files) and `trading/crypto/` (34 files): 101 of 109 files were opened; the 8 skipped were trivial (`__init__.py`/thin re-export files).
- `dashboard/web/` (React/JS frontend) and `dashboard/static/dash-assets/` (compiled JS bundles) were noted by existence/purpose only, not read as source — out of scope for a Python-capability inventory and not human-authored (build output).
- Root-level `run_*.py` entry-point scripts (48 total): all were at least docstring/import-read; roughly 40 were read to full logic depth, the remainder (mostly thin wrappers around modules covered in depth elsewhere, e.g. `run_strategy_t8.py`, `run_crypto_trading.py`) were cross-verified via their target module instead of opened directly.

No git history, commit messages, or issue tracker were consulted — this is a working-tree snapshot inventory only. Every row's evidence path was captured by the mining pass that read the file; this merge pass did not re-verify each citation against the source tree line-by-line, only checked structural table validity (column count, valid Category/State enum values), de-duplicated exact-name collisions (none found across any of the six regions), and normalized a handful of State-column entries that were mined with parenthetical qualifiers (e.g. "IMPLEMENTED (env-wired; module not opened)") down to the strict three-value enum, preserving the qualifier's substance in the "What it does" or evidence cell where it mattered.
