# Strategies as Evolved Programs — What the Published Record Actually Shows

**Provenance.** Researched 2026-08-08 via four parallel `sonnet` subagents (per the standing model-selection rule: research/docs lookup → sonnet, synthesis → main thread/opus), each fetching primary sources directly (arxiv.org full text, Nature/publisher pages, OpenReview API, ACL Anthology, `gh` CLI for repo facts) rather than relying on search-snippet paraphrase. Areas: (A) canonical general-purpose evolved-program systems, (B) finance-specific evolved-alpha systems, (C) DSL restriction + quality-diversity search, (D) the overfitting/failure record and multiple-testing correction. Synthesis, cross-checking, and contradiction-resolution below were done on the main thread, not delegated.

---

## VERDICT

Evolving **programs** rather than tuning **parameters** is a real, working mechanism — but the published record supports it only within a narrow, mechanically-verifiable class of problems, and the finance-specific literature does not yet demonstrate it at the level this system's design requires. Five points carry the most weight:

1. **Peer review is uneven and the most architecturally relevant system fails it.** Of the eight canonical systems, only **FunSearch** clears a genuinely high peer-review bar (*Nature*). Five more (ADAS, Eureka, STOP, EvoPrompt, ShinkaEvolve) cleared real but lower-rigor ML-conference peer review (ICLR/COLM). **AlphaEvolve** — the system whose framing (evolving whole codebases, not single functions) is closest to "evolve a full trading strategy" — is a **self-published, closed-source corporate white paper with no peer review at all**, corroborated by only one third-party GitHub issue on one sub-result.
2. **Every finance-specific evolved-alpha system found evolves factors, not strategies.** All six papers surveyed (QuantaAlpha, FactorMiner, CogAlpha, AlphaAgentEvo, XAlpha, AlphaAgent) evolve alpha **formulas/factor code only**; portfolio construction, position sizing, and risk logic are uniformly a fixed, hand-written downstream layer, never evolved. This is a direct scope gap against a requirement that "all signals, weights and regimes" be learned — none of these systems learn the weighting or regime layer; they learn only the signal layer and bolt it onto hardcoded portfolio logic.
3. **The one number every finance paper omits is the one multiple-testing correction needs most.** Five of six finance papers do not report the total number of candidate strategies/factors generated and evaluated (only fragments: per-round pool size, per-factor time). In one case (AlphaAgentEvo, ICLR 2026) a reviewer explicitly asked for this number on the record and it went unanswered.
4. **The failure record is unambiguous and convergent across three independent statistical frameworks.** Deflated Sharpe Ratio (Bailey & López de Prado), Bonferroni/Holm/BHY (Harvey, Liu & Zhu), and PBO/CSCV (Bailey, Borwein, López de Prado & Zhu) all show the same shape: the bar a genuinely-skilled strategy must clear rises monotonically — and never falls — as the number of trials grows. None of the six finance-evolved-alpha papers apply any of these corrections to their reported results.
5. **A diverse (quality-diversity) archive does not get a discount on this correction — if anything the opposite.** The correction is driven by the total number of candidates *evaluated*, not the number *retained*. A QD archive that keeps many behaviorally-different strategies is more honest about how many trials it ran (nothing is thrown away as "not the best"), but it does not reduce the true trial count — and the finance literature's own worst-omission (point 3) means the archive's true trial count is exactly the number these systems don't report.

**Bottom line for the target system:** the mechanism is legitimate and has real published grounding at the general-program-search level (FunSearch, and with caveats AlphaEvolve/ADAS/Eureka/ShinkaEvolve), but importing it into "no hardcoded alpha logic, everything learned" trading requires: (a) evolving the full strategy — including portfolio/weighting/regime logic — which no surveyed finance paper does; (b) logging and reporting the true total trial count, not just the retained archive; and (c) applying a Bailey/Harvey-Liu-Zhu-style correction keyed to that true count before trusting any out-of-sample number, which is a step the entire finance-specific crop currently skips.

**The pattern, not just the per-paper detail:**
1. **All six evolve alpha factors/formulas, never a full strategy.** Portfolio construction (ranking, weighting, sizing) is a fixed, hand-written downstream layer in every case — a direct architectural mismatch with a "no hardcoded alpha logic, all weights and regimes learned" requirement.
2. **Total search/compute budget is the most consistently missing number.** 5 of 6 papers give only fragments; AlphaAgentEvo's gap is on the public ICLR review record, not merely inferred.
3. **"Sealed test set" is asserted far more often than demonstrated.** Only XAlpha's design and, more weakly, FactorMiner's single Table protocol give enough detail to believe it; the other four use a nominal chronological split without describing how the validation window was actually used during search, leaving open whether test-period performance leaked back into iterative selection.
4. **Redundancy filtering is real but inconsistent in rigor** — hard numeric correlation gates in three papers (QuantaAlpha 0.7, FactorMiner 0.5, XAlpha 0.95), a soft unthresholded regularizer in one (AlphaAgent), and none at all against an external library in two (CogAlpha, AlphaAgentEvo).
5. **Transaction costs are the best-covered dimension** (5 of 6 state an explicit fee schedule, typically the CN A-share 0.05%/0.15% convention) **but none model market impact/slippage beyond a flat fee**, and AlphaAgentEvo's own reviewers flagged this gap explicitly.

## 3. The DSL question

**Search efficiency.** McKay, Hoai, Whigham, Shan & O'Neill's survey of grammar-based GP (*Genetic Programming and Evolvable Machines* 11:365–396, `10.1007/s10710-010-9109-y`) states the core tradeoff directly: *"The main benefit of restricting the search space is to reduce the search cost to the minimum necessary to find a solution, but it comes with the concomitant risk that the solution may not be within the search space defined by the grammar."* Concretely, dimensionally-constrained grammars in physics-formula discovery *"reduce the search space size by many orders of magnitude, turning a clearly infeasible problem into a feasible one."* On the finance side specifically, Ren, Qin & Li (arXiv:2412.00896) report that random sampling 10,000 GP-generated alphas from an *unconstrained* space found fewer than 3% effective (IC > 0.03) — direct empirical evidence of the wasted-evaluation cost of not constraining the space; restricting tree structure "completely avoids the 'code bloat' problem."

**Overfitting resistance.** The same McKay et al. survey makes the theoretical link explicit and precise: grammar constraint *"reduces the VC dimensionality of the corresponding solution... the data size required to justify acceptance of a formula of such complexity would be simply astronomical, without the grammar constraints."* But this is **not treated as settled** in the empirical GP-for-finance literature: Tuite, Agapitos, O'Neill & Brabazon ("Tackling Overfitting in Evolutionary-Driven Financial Model Induction," Springer, PDF fetched directly) explicitly cites the counter-position (Domingos) that *"overfitting is an unwanted side-effect not of complexity"* per se. Becker & Seshadri (WPI-CS-TR-03-09) found that adding a complexity-penalizing fitness term produced measurably less-overfit trees — a direct empirical result in favor of constraint, but via a fitness penalty rather than a hard DSL boundary.

**Expressiveness cost.** McKay et al. again, directly: restricting the search space carries *"the obvious risk that the constraints may render the solution inaccessible: if the grammar is wrongly chosen, the solution may not even lie within the search space defined by the grammar,"* and grammar-constrained spaces tend to be sparser and less connected, making search itself harder even within the smaller space. **No paper was found documenting a concrete, specific trading-strategy structure excluded by a DSL constraint** — this expressiveness-cost argument exists in the GP theory literature generally, not as a trading-domain case study; that absence is itself worth noting rather than papering over.

**Why FunSearch and AlphaEvolve chose free-form code over a DSL.** FunSearch restricts to one function inside a human-written skeleton (a middle ground: free-form within a narrow surface, not a constrained grammar). AlphaEvolve goes further — full-codebase, multi-language evolution — and its paper states the reasoning directly: classical GP methods' *"use of handwritten evolution operators... can be hard to design and may fail to capture important properties of the domain. In contrast, AlphaEvolve uses LLMs to automate the construction of these operators."* In effect: an LLM's pretrained world-knowledge is being used as a substitute for a hand-designed DSL, betting that the model's own priors constrain the effective search space better than an explicit grammar would, without hard-excluding solutions the grammar-designer didn't anticipate.

Sources: McKay et al., `10.1007/s10710-010-9109-y`, https://ncra.ucd.ie/papers/grammarbasedGPaSurvey2010.pdf; Ren, Qin & Li, arXiv:2412.00896, https://arxiv.org/abs/2412.00896; Novikov et al., arXiv:2506.13131 (§5, Related Work); Tuite et al., https://ncra.ucd.ie/papers/TacklingOverfit.pdf; Becker & Seshadri, https://ftp.cs.wpi.edu/pub/techreports/pdf/03-09.pdf.

## 4. Quality-diversity search

**Mechanism.** MAP-Elites (Mouret & Clune, arXiv:1504.04909) maintains one elite per cell of a **user-defined, discretized behavior space**, replacing an incumbent only when a higher-fitness candidate lands in its cell — illuminating a whole space of good-but-different solutions rather than converging to one optimum. Cully, Clune, Tarapore & Mouret's companion *Nature* paper (arXiv:1407.3501) gives the concrete mechanics: a hexapod robot's 6-dimensional behavior space (leg ground-contact duty factor), discretized at 5 values/dimension (up to 5⁶ = 15,625 cells), each holding one elite genome + fitness score.

**Applications to trading strategy search — genuinely rare, and the two agents researching this in parallel produced a correction worth surfacing.** The DSL/QD research leg searched hard (five distinct query variants) and found only **one** direct hit: de Witt & Pakkanen, "Diverse Approaches to Optimal Execution Schedule Generation" (arXiv:2601.22113, Jan 2026) — the first application of MAP-Elites to trade execution, using a **liquidity × volatility** 2D behavior grid over PPO-trained regime-specialist policies, reporting 8–10% performance improvement within specialist niches (too recent for independent citation/replication). Separately, the failure-record research leg — searching for evolutionary trading-strategy overfitting evidence — surfaced a **second** MAP-Elites-in-finance paper the first leg's queries missed: **MadEvolve/QuantEvolve** (arXiv:2605.23007), an AlphaEvolve-inspired framework applying MAP-Elites (5 islands, migration every 5 generations) to quantitative-finance tasks, with a dedicated section explicitly asking "are we doing research, or are we p-hacking?" and comparing observed in-sample/out-of-sample degradation against the Bailey et al. multiple-testing discount. **This is the single most directly relevant paper found in the entire sweep** — a QD-archive trading-strategy search that is itself explicitly reasoning about the exact correction question this report's Section 5 addresses — and it was caught only by cross-checking two independently-run research legs against each other, which is itself a reminder that "no paper found" claims from a single search pass should be treated as provisional.

Beyond these two, **no paper was found** combining MAP-Elites/QD with GP-evolved alpha-factor or entry/exit-rule discovery specifically (as opposed to execution scheduling or the general MadEvolve framework) — reported here as a genuine near-absence, not stretched from an adjacent RL-ensemble-diversity paper (e.g. arXiv:2210.01774) that does not use archive/grid QD mechanics.

**Diversity as an anti-correlation hedge — theoretically motivated, not yet explicitly published for evolved-strategy archives.** The classical Markowitz (1952) argument — combining low/negatively-correlated *assets* lowers portfolio variance — is well established and is explicitly invoked by Yuksel (arXiv:2307.07811), whose "Generative Meta-Learning Robust Quality-Diversity Portfolio" minimizes *"the maximum correlation in-between sub-portfolios"* using a QD-style diversity objective, citing Markowitz directly. But Yuksel's method diversifies **asset-allocation sub-portfolios**, not an archive of evolved trading-strategy *programs*, and does not use MAP-Elites grid mechanics. **No paper found makes the precise bridge** — "because a MAP-Elites archive enforces behavioral diversity among evolved strategies, the resulting strategy portfolio has lower correlated-drawdown risk than a fitness-only-optimized population" — explicitly and for programs (as opposed to asset weights). This should be treated as a plausible, theoretically-grounded inference, not an established literature claim.

**How behavior descriptors get chosen.** Pugh, Soros & Stanley (`10.3389/frobt.2016.00040`) are explicit that descriptor choice is a human design decision — *"the experimenter selects some subset of behavioral features of interest to form a behavior characterization"* — and that alignment between the descriptor space and the fitness objective matters (misaligned descriptors help escape deceptive optima; aligned ones speed convergence). Concrete descriptor categories actually cited in fetched primary sources: leg duty-factor and (x,y) end-effector position (Cully et al. 2015, robotics); molecule size/cost (Mouret & Clune 2015's own example); **liquidity × volatility market regime** (de Witt & Pakkanen 2026 — the only trading-specific citation). By structural analogy — and explicitly flagged here as extrapolation, not citation — plausible trading-strategy descriptors include holding-period/turnover, drawdown-shape/recovery-time, and correlation-to-benchmark-or-to-archive-member; only the liquidity/volatility axis has direct published support.

Sources: Mouret & Clune, arXiv:1504.04909; Cully, Clune, Tarapore & Mouret, *Nature* 521:503–507, arXiv:1407.3501; de Witt & Pakkanen, arXiv:2601.22113; Yuksel, arXiv:2307.07811; MadEvolve/QuantEvolve, arXiv:2605.23007, https://arxiv.org/html/2605.23007v1; Pugh, Soros & Stanley, `10.3389/frobt.2016.00040`; Cully & Demiris, arXiv:1708.09251; Chatzilygeroudis, Cully, Vassiliades & Mouret, arXiv:2012.04322.

## 5. The failure record

**Direct evidence of GP-evolved trading strategies overfitting.** Allen & Karjalainen ("Using genetic algorithms to find technical trading rules," *Journal of Financial Economics* 51:245–271, 1999; PDF fetched directly) evolved trading rules for the S&P 500 (daily data 1929–1995) across 10 genuinely out-of-sample train/select/test splits. Result, in the paper's own words: *"After transaction costs, the rules do not earn consistent excess returns over a simple buy-and-hold strategy in the out-of-sample test periods."* Exact numbers: average out-of-sample excess return over buy-and-hold at 0.25% transaction costs was **−2.05%/year**, with only 17 of 89 evolved rules positive out-of-sample; a one-day signal-delay robustness check largely eliminated even that residual edge, indicating the rules were exploiting well-known low-order serial correlation rather than a genuine tradable pattern.

The picture is not uniformly negative, but the record of the *exceptions* is itself instructive. Neely, Weller & Dittmar's 1997 GP study of FX rules reportedly found significant out-of-sample profitability 1981–1995 (summarized via Neely & Weller's 2011 St. Louis Fed survey, fetched directly, since the original *JFQA* article was paywalled) — but the same research group's later work reversed this on genuinely later-arriving data: *"As the profitability of those simple rules became widely publicized in the academic literature, the profitability of the rules disappeared"* (Neely, Weller & Ulrich 2009, summarized in the same survey). Neely & Weller (2003, intraday FX) found *"no evidence of positive excess returns"* once realistic transaction costs and normal-hours trading were imposed; Kozhan & Salmon (2010) found a GP-based GBP/USD strategy profitable in 2003 but with those profits gone by 2008, attributed to crowding from the rise of algorithmic trading. The consistent shape across two decades of this literature: apparent GP-discovered edges are real often enough to publish, but decay or vanish once (a) genuinely new out-of-sample data arrives, or (b) the pattern becomes known and arbitraged away.

**Multiple-testing correction — three independently-fetched frameworks, all showing the same monotonic direction.**

- **Deflated Sharpe Ratio** (Bailey & López de Prado, *Journal of Portfolio Management* 40(5):94–107, 2014; PDF fetched and read in full). The expected maximum Sharpe ratio achievable by chance alone, given N independent trials, is `E[max{SR_n}] ≈ μ + σ·[(1−γ)·Z⁻¹(1−1/N) + γ·Z⁻¹(1−1/(N·e))]` (γ = Euler–Mascheroni constant ≈ 0.5772) — monotonically increasing and concave in N. Worked example from the paper: a strategist reporting annualized SR 2.5 from N=100 trials gets **Deflated SR = 0.9004 < 0.95 → rejected as not significant**, despite the headline number; had the same result come from only N=46 trials, it would have cleared the 0.95 bar. The same discovery is significant or not **purely as a function of how many trials preceded it.**
- **Bonferroni / Holm / BHY** (Harvey, Liu & Zhu, NBER WP 20592 / *Review of Financial Studies* 29(1):5–68, 2016; fetched and read in full). Applied to 316 published return-predicting factors, all three correction families require a rising t-ratio threshold as the factor count M grows — from the paper's own exact table: **t=2.0 requires M=1 test; t=3.0 requires M=19; t=4.0 requires M=789; t=5.0 requires M=87,214; t=6.0 requires M=25,340,000.** The paper's headline recommendation given the true (including unpublished/discarded) trial count is a minimum t-ratio of **3.0**, and up to **3.18–3.78** once hidden trials are modeled — never a lower bar.
- **Probability of Backtest Overfitting / CSCV** (Bailey, Borwein, López de Prado & Zhu, *Journal of Computational Finance*, 2015; fetched and read in full). A worked example applies an 8,800-configuration parameter sweep to a **pure random-walk** series: the in-sample result looks strong (annualized SR 1.27, PSR-stat 2.83) but CSCV analysis correctly flags **PBO = 55%**, with 53% of out-of-sample Sharpe ratios negative — the framework correctly unmasking a backtest as overfit that naive significance testing would have passed.

**All three frameworks move in the same direction, without exception across every source fetched: the required bar rises — never falls — as the number of trials grows.**

**Does any paper connect archive/QD diversity size to the effective trial count?** No paper was found making this connection with a precise formula. The closest is **MadEvolve/QuantEvolve** (arXiv:2605.23007, discussed in Section 4), which runs a MAP-Elites-based evolutionary search over trading strategies and explicitly frames its central question in Bailey-et-al. multiple-testing terms — including the statement that a finer parameter sweep per candidate means *"the effective number of trials... would no longer be a handful of LLM mutations but a continuous sweep of each parameter's local optimum, feeding directly into the multiple-testing inflation"* — but it discusses archive mechanics and multiple-testing theory in separate sections without explicitly deriving "archive size N ⇒ effective trial count ≥ N."

**In the absence of a paper making that exact connection, the logic is nonetheless directly supported by the general frameworks themselves, not merely inferred by this report:** Bailey & López de Prado's own N is explicitly defined as the full set of trials evaluated (their worked example: "He backtests alternative configurations... many combinations yield an annualized SR of 2, with a particular one yielding an SR of 2.5" — N=100 covers *all* configurations tried, not just the reported one). Harvey, Liu & Zhu build the identical point into their headline result: their true-M correction (raising the recommended threshold from t=2.78 to t=3.18) exists specifically because most tried-and-discarded factors are *never reported*, so the visible count understates the true trial count. **A quality-diversity archive is, on this logic, the opposite failure mode from the one these papers were built to catch — it makes more of the true trial count visible (nothing is discarded as "not the winner") — but it does not shrink the true trial count, and the correction must still be keyed to the total number of candidates evaluated to build the archive, not the number of cells it ends up occupying.** Given that Section 2 found 5 of 6 finance-specific papers do not report that total, this is the single sharpest unresolved gap between the failure-record literature's own stated requirements and the finance-specific evolved-alpha crop's actual reporting practice.
